**Finding/Creating Classes**
* Good classes are used to display the whole system, you need to be specific and display the relationship.
___
**Tentative Classes**
* Comes from SRS and Domain Knowledge. step one of creating a class
___
**Keep The Right Classes**
* Don't use redundant classes, irrelevant classes, or vague classes
* Remove attributes, Operations, Roles, and Implementation constructs that don't help with design.
* Define datatypes and parameters when it comes to expressing value.
___
**Defining The Class Attributes**
* "-" private: Same class methods/attributes can access this attribute.
* "+" public: Any class can access the attribute
* "#" protected: Same class or sub-class can access the attribute
* "~" package: Classes within the same package can access the attribute
___
**Operations**
* Functions or actions of a certain class
___
**Relationships Between Classes**
* Dependency: You need a certain class do move to another class
* Association: There is a connection between two classes (can be one-way, or two-way)
* Aggregation: Two classes can exist individually even one is destroyed, but they reference each other.
* Composition: When one class contains object of another class
* Inheritance: Takes the attributes the methods of the superclass or parent class
* Multiplicity: The number of object associated with an object
	* 1...x
	* x...1
	* m...n
	* 4
___
**Derived Association And Attributes**
