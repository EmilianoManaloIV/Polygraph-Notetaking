**Practices Of Software Engineering**
* **Prepare** Understand the cases of the problem and what you are trying to solve.
* **Think:** What is your possible solution to fulfill the problem and requirements that is present.
* **Execute/Implement:** Carry out the plan and start creating the execution.
* **Verify/Validate:** Examine the results for accuracy and security flaws
___
**Understanding The Requirements/Problem**
* Who are the stakeholders? Business, end-users, students, etc.
	* EX: Who are the stakeholders of Canvas? Students, Faculty, Board.
* What are the unknowns? What data are we working with, what functions do we need, what are the features that are required?
* **Can The Problem Be Compartmentalized?** Can we breakdown the bigger problem into smaller pieces that makes it easier to execute.
	* What the benefits of the solution? Does it need a lot of resources? Does it need other things? These are all things to consider.
* **Can The Problem Be Represented Graphically**
	* Can an analysis model be created?
___
**Plan A Solution**
* Is this a similar problem to something you experienced before? Or an issue that is very similar.
	* If so, is the same approach usable? So that you don't have to recreate it from scratch.
* Can subproblems be defined, are you able to compartmentalize the problem itself.
* Is there a model you can reference to that satisfied your requirement, cost, time, etc.
___
**Carry Out The Plan**
* Does the source code add to the modeling in the planning phase?
* Has the code been reviewed for verification? Planning? Testing?
___
**Examine The Result**
* Was there proper testing algorithms to test the system and fulfill their requirements.
* Has the software validated all stakeholder requirements and passed all major testing functions.
	* Functionality, but discretion is also the most important part of the program.
___
**Hooker's General Principles**
* 1. Does the functionality actually providing use to the user (DON'T DO THINGS THAT ADD NOTHING TO THE USER)
* 2. KISS: Keep it simple & stupid, make it simple
* 3. Have a clear vision in what you are trying to solve.
* 4. What you create will be used by others
* 5. Be open to future developments, do not constrict yourself
* 6. Plan ahead and Reuse - reduces production overhead
* 7. Think with abstraction in mind, think ahead to plan your problem solving
___
